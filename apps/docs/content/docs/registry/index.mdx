The registry works like [shadcn/ui](https://ui.shadcn.com), for PDFs. Components are not a dependency: the shadcn CLI copies their source into your project, and you own and edit the code.

- **`@ui-registry/pdf`** (npm) provides the primitives: `Block`, `Text`, `Page`, the Tailwind engine, fonts.
- **The registry** provides components (`Table`, `Card`, `Badge`…) and complete blocks (`Invoice`) built on top of them.

## Installation

Your project needs a `components.json` (created by `npx shadcn init`). Then add any item by URL:

```bash
npx shadcn add https://pdf-primitives.vercel.app/r/invoice.json
```

The CLI installs `@ui-registry/pdf` and the components the item depends on.

## Where files go

PDF components are installed in **`components/pdf/`**, not `components/ui/`, so they never overwrite the HTML shadcn components with the same name (`card`, `table`, `badge`…).

```
components/
├── ui/          ← your HTML shadcn components
│   └── card.tsx
└── pdf/         ← PDF components from this registry
    ├── card.tsx
    ├── table.tsx
    └── invoice.tsx
```

## Theming

Components only use semantic colors (`bg-primary`, `text-muted-foreground`, `border-border`…). Pass your theme to `<Document theme>` — or to the `theme` prop of a block — to match your brand. See [Theming](/docs/theming).

## Available items

| Item | Type | Description |
|------|------|-------------|
| [Heading](/docs/registry/heading) | component | Document headings (levels 1–4) |
| [Separator](/docs/registry/separator) | component | Horizontal or vertical divider |
| [Badge](/docs/registry/badge) | component | Status label with variants |
| [Card](/docs/registry/card) | component | Bordered container with header and footer |
| [Table](/docs/registry/table) | component | Table with a repeating header |
| [Page Footer](/docs/registry/page-footer) | component | Footer on every page, with page numbers |
| [Invoice](/docs/registry/invoice) | block | Complete multi-page invoice |
